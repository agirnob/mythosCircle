## Findings

### Architecture delta — single-writer holds; provider/config pattern established twice, consistently

- **AD-1 single-writer HOLDS across the entire epic.** The store owns every `media` row write/delete: `add_media` (4-1), `delete_entity_media` inside `_delete_entity`'s transaction + `delete_campaign`'s bulk sweep (4-3), and the export's media read rides the snapshot session (4-3 review). The media service (files) and API never touch the table directly — verified in the 4-3 review and re-confirmed live. — pass
- **AD-10 media ownership HOLDS.** Files at `media/{campaign}/{entity}/`, manifest rows as index of record, reclaim on entity + campaign delete, reference-validated export (`available` flag). The delete path is rows-in-txn → files post-commit (rows-first, no dangling references); export flags broken refs, never drops them (FR14). — pass
- **Provider adapter discipline exported intact.** 4-4/4-5 mirror the 4-1/4-2 leaf-adapter shape: `Callable[..., bytes]`, `ProviderError` family from `app.providers.llm`, injectable `transport`, kwargs-only `settings`. The `[image]`/`[video] backend` switch pattern landed twice (4-4, 4-5) with the same env > config > default precedence; 4-5's review tightened the backend resolution to `Literal["openai","comfyui"]` and introduced a shared `ProviderSettings` protocol so the worker's comfyui branches type-check with zero `type: ignore`. — pass
- **run_video's portrait gate is comfyui-scoped (4-5 review critical).** The no-portrait gate originally fired on both backends, breaking the default OpenAI path and 4-2's "unchanged" acceptance; the review caught it and scoped resolution to `backend="comfyui"`. The OpenAI path passes `first_frame=None` — 4-2 runs exactly as shipped. — pass

### Duplication map — two twin clusters from the adapter/runner discipline

1. **`comfyui.py` (328) and `comfyui_video.py` (389) are near-twins.** Both carry `_SAFE_PROMPT_ID`, `_request_timeout`, `_PROMPT_PATH`, `_POLL_INTERVAL`, the submit→poll `/history`→fetch `/view` scaffolding — 11 shared pattern atoms each. The 4-5 spec deliberately mirrored 4-4 ("sibling provider"), and the two's different payloads (prompt widget vs prompt + first_frame staging) justify separate modules — but the shared scaffolding (deadline bookkeeping, prompt-id validation, poll loop) is copied, not imported. A bug fixed in one (e.g. the review-round non-dict-inputs guards landed in BOTH) must be re-applied in the other. — defer (refactor when a third ComfyUI-backed provider appears, or now as a shared `_comfyui` helper module)
2. **`run_portrait` and `run_video` in media/service.py share the atomic-write + `add_media` + cancel-race discipline** (temp+rename, file-before-row, `_job_still_running` poll, complete/fail-vs-`JobStateConflictError`). Not identical (PNG vs mp4 guards, prompt builders), but the write/manifest tail is the same shape written twice. — defer (shared `_write_media_file` helper; low urgency — 4-3 review already extracted the reclaim twin)
3. **epic-3's AR24-profile refactor debt GREW.** WorldView went 975 → 1326 lines (+352: portrait + video blocks); CandidatesView 1109 → 1129. The duplicated LORE_FIELDS/FIELD_LABELS/EDGE_VOCAB/COUNTER_TYPES sets from epic-3-item-2 are untouched (3.3's review only fixed CandidatesView's copy) — see Previous-retro follow-through.
