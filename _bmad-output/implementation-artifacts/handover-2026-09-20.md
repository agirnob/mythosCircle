## The shipped contracts

- **Restore** (`backend/app/core/restore.py`, stdlib, mirrors backup.py):
  `python -m app.core.restore verify|apply <snapshot-dir> [--data-dir DIR]`
  (env: `MYTHOSCIRCLE_DATA_DIR`, `MYTHOSCIRCLE_MEDIA_DIR`). Destination DB
  name comes from the manifest `db.file` (dev `mythos.db` included).
  `verify` is the **6-5 gate instrument**. Snapshot format = 6-1 frozen
  (db + db.sha256 sidecar + manifest.json + manifest.json.sha256 +
  media.tar.gz optional; sidecar line `<64-hex>  <name>\n`).
- **Deletion** (unchanged contract, now proven): `DELETE
  /api/campaigns/{id}` body `{"confirm": true}` → 204; missing/false →
  400; foreign/unknown → 404 no-oracle; store `delete_campaign` one
  transaction (event → revision → entity → edge → proposed_candidate →
  job → media → campaign); post-commit best-effort media-dir reclaim
  never fails the 204. UI: type-the-title confirm in CampaignsView.
- **Deploy flow (owner instruction 2026-09-20, laptop = 192.168.1.21)**:
  NO git remote — the laptop is compose + images + scp'd ops scripts, not
  a checkout. Update it after every backend/frontend change:
  - api image: `docker build -f deploy/docker/Dockerfile.api -t mythoscircle-api:local .`
    → `docker save mythoscircle-api:local | gzip | ssh -i ~/.ssh/mythos_laptop homest@192.168.1.21 "gunzip | docker load"`
    → `ssh ... 'cd ~ && docker compose -p mythoscircle -f mythos-redeploy.yml up -d api'`
  - ops script: `scp -i ~/.ssh/mythos_laptop deploy/restore.docker.sh homest@192.168.1.21:~/restore.docker.sh`
  - verify: `curl -s -o /dev/null -w "%{http_code}" https://world.miscco.uk/login` → 200
