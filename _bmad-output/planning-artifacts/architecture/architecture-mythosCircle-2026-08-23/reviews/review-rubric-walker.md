## Findings (ranked)

1. **[FAIL — item 1] AD-17 leaves the WebSocket job-progress/queue-position message envelope undecided.** The rule names the channel (REST + WebSocket) and the REST error envelope, but the WS frame schema (progress, position, completion/failure) is exactly the shared contract the rule claims to prevent drifting between the backend and Vue builders. Fix: one line in AD-17, e.g. WS frames are `{type, job_id, position?, status?, ...}` using the same ULID/ISO-8601/envelope conventions as REST.
2. **[FAIL — item 1] AD-9's "session token" leaves token transport undecided** (httpOnly cookie vs. Authorization header). The FastAPI builder and the Vue builder must agree on how every request is authenticated; the spine is silent. Fix: one clause in AD-9 (recommend httpOnly cookie on the Caddy-origin domain).
3. **[Nit] ER diagram omits ACCOUNT and the CAMPAIGN→owner edge** that AD-9 (per-campaign ownership, private) and AD-13 (accounts in the same SQLite store) require — a store builder working from the diagram alone would miss the accounts table and the ownership constraint.
4. **[Nit] AD-7 vs. AD-18 vocabulary tension:** AD-7's typed event shape hardcodes "campaign-day" while AD-18 allows month/year/century granularity; the event field should be named for the unit-agnostic campaign time value.
5. **[Nit] Cosmetic:** AD-19 Binds "7 Later" missing § prefix; CRON→DB arrow solid (deployment) vs. dashed (dep graph); AD-20's visualizer boundary phrasing ("may not reach into the Pinia world-state stores") is ambiguous — it should say the visualizer consumes the store and never fetches or owns world state.

## Verdict rationale

The spine is close to gate quality: 24 of 25 ADs are enforceable, PRD coverage is complete, deferrals are bounded, the stack is honest seed, and the three diagrams encode the one-writer/single-store rules correctly. It fails on exactly one rubric item — the one that protects the level below: two builders (backend queue/WS emitter, Vue progress UI) would have to negotiate the WS message contract, and the auth-token transport, on their own. Both fixes are one-line AD amendments (AD-17, AD-9); the nits are optional cleanups. Recommend: amend AD-17 + AD-9, re-walk item 1, then PASS.
