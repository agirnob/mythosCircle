# Image-grounded H3 prompt enhancement

For a boss-tier character, write **Your video direction** and select **Enhance with portrait**. The selected private portrait's actual PNG/JPEG bytes and the written direction are sent through the administrator's normal LLM routing. The configured model must support image input. Entity profile text and world lore are excluded from the enhancement's narrative context; visual details come from the image.

The editable draft uses MiniMax H3's image-to-video layout: a frame-zero alignment line followed by `integrated_multimodal_description`, `overall_soundscape` and `non_diegetic_music`, separated by blank lines. Its instructions follow the [official H3 prompting guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/raw/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md). The default is one continuous shot within the configured 15-second workflow. Requested complete silence and no music use `N/A`.

Review and edit the draft, then separately choose **Render reveal video**. The approved text is sent verbatim. An enhanced prompt retains its original portrait ID across edits, refreshes, queued completion and newer portraits. The bound image must still exist and belong to that character and campaign. Image-bound rendering requires ComfyUI; the text-only video adapter cannot silently discard its source frame. Existing manual prompts and unbound rendering remain usable.

Your direction, approved text and image binding are saved locally per campaign and entity. If the bound image was deleted or a newer portrait is wanted, **Use latest portrait** explicitly discards the old enhancement binding while keeping the editable text as a manual prompt. Matching image-aware jobs can be recovered after list synchronization, including when local browser storage is unavailable. Edits made while enhancement runs are kept; the completed enhancement is offered separately for review. A failed provider, unsupported vision model or malformed response leaves the inputs editable, without substituting an appearance-based enhancement. Previously queued entity-only draft jobs retain their old compatibility behavior.

Enhancement enqueues exactly `{entity_id, image_id, prompt}`; `prompt` is a nonblank direction of at most 8,000 characters. Rendering accepts an optional `image_id` with a required approved prompt. Image ownership/kind is checked at enqueue and execution. Local image reads enforce directory containment, a 20 MiB compressed limit, a 16 megapixel limit, and PNG/JPEG verification. No new media URL or public access is introduced. Image data is per-call only and excluded from settings representations and generation journals. Enhancement writes only its queued job result, without changing world state or producing media.
